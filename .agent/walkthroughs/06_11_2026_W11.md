# Nhật Ký Thực Thi (Walkthrough) - 06/11/2026 (W11)

## Mục Tiêu Phiên Làm Việc
Khắc phục triệt để lỗi màn hình `Error response: Error code: 404 - File not found` khi truy cập đường dẫn SPA client-side routing (như `http://localhost:5173/la-so-tu-vi`).

---

## 1. Nguyên Nhân Sự Cố
- **Nguyên nhân chính**: Một tiến trình nền cũ `python.exe -m http.server 5173 --directory frontend/public` (PID 14604) còn sót lại trong hệ thống và chiếm dụng cổng `5173`. Do `http.server` của Python chỉ là một máy chủ file tĩnh đơn giản (không có SPA fallback), khi trình duyệt yêu cầu đường dẫn `/la-so-tu-vi`, nó tìm kiếm file thực tế trên đĩa và trả về trang lỗi mặc định của Python:
  ```html
  <title>Error response</title>
  <h1>Error response</h1>
  <p>Error code: 404</p>
  <p>Message: File not found.</p>
  <p>Error code explanation: 404 - Nothing matches the given URI.</p>
  ```
- **Nguyên nhân phụ**: Lệnh `free_port(5173)` trước đó chỉ lọc các dòng có trạng thái `LISTENING` theo định dạng cũ nên có thể bỏ sót các socket bị chiếm dụng ở một số trạng thái kết nối; đồng thời lệnh gọi Vite trong script được tối ưu trực tiếp bằng `node.exe` thực thi `vite.js --host`.

---

## 2. Các Bước Đã Xử Lý
1. **Dập tắt tiến trình chiếm cổng cũ**: Đã buộc dừng tiến trình PID 14604 (`python.exe -m http.server 5173`).
2. **Nâng cấp thuật toán `free_port(port)` trong `start.py`**: Kiểm tra chính xác địa chỉ cổng cục bộ `local_addr.endswith(f":{port}")` để dọn dẹp triệt để mọi tiến trình đang chiếm cổng trên Windows mà không bị sót.
3. **Tối ưu hóa lệnh gọi Vite**: Trỏ trực tiếp `node.exe` vào đường dẫn tuyệt đối của `frontend/node_modules/vite/bin/vite.js --host`, đảm bảo Vite Dev Server khởi động chính xác 100% với hỗ trợ SPA fallback (tự động điều hướng tất cả các route React như `/la-so-tu-vi` về `index.html`).

---

## 3. Kết Quả Kiểm Thử

- Giao diện SPA React nạp đầy đủ HTML, `@vite/client` và các module của trang Lập Lá Số.
