1. **Giải quyết triệt để lỗi "cố định phiên bản"**: Các thiết bị trong mạng LAN khi reload không cập nhật được thay đổi mã nguồn mới nhất.
2. **Loại bỏ các tính năng dư thừa**: Tinh gọn script `deployment/scripts/start.py`, loại bỏ cơ chế phục vụ bản build tĩnh `releases/dist` qua cổng 8443, loại bỏ rate limiter in-memory và quy trình sinh chứng chỉ SSL tự ký phức tạp khi phát triển.

## 1. Nguyên Nhân Sự Cố
- Trước đây, máy chủ LAN phục vụ các thiết bị qua cổng `8443` (hoặc `8080`) bằng cách đọc trực tiếp từ thư mục `releases/dist` (sản phẩm build cũ). Mỗi khi chỉnh sửa mã nguồn ở `frontend/src`, các file này không hề thay đổi trừ khi chạy lệnh `npm run build`. Do đó, người dùng reload trang trên điện thoại hay thiết bị khác đều bị "đóng băng" ở phiên bản cũ.
- Vite Dev Server đã có sẵn cơ chế Reverse Proxy `/api` trỏ về Flask Backend (Port 8080) và hỗ trợ lắng nghe trên toàn mạng (`--host 0.0.0.0`).

## 2. Giải Pháp Triển Khai
Tái cấu trúc tinh gọn [`deployment/scripts/start.py`](file:///e:/Documents/T%E1%BB%AD%20Vi%20H%E1%BB%93ng%20%C3%82n%20Website/deployment/scripts/start.py):
1. **Frontend Vite Dev Server (Cổng 5173 - Host `0.0.0.0`)**:
   - Phục vụ trực tiếp cho cả máy tính (`http://localhost:5173`) và tất cả các thiết bị truy cập qua Wi-Fi (`http://<IP_LAN>:5173`).
   - Kích hoạt cơ chế **Hot Module Replacement (HMR)** và **Live Reload**: Mọi chỉnh sửa mã nguồn frontend/backend đều phản ánh tức thì khi reload/lưu file mà không cần build lại.
   - Vite tự động điều hướng các API request `/api/*` về Flask Backend (`http://127.0.0.1:8080`) an toàn và minh bạch.
2. **Backend Core Engine (Flask - Cổng 8080)**:
   - Chạy độc lập, xác thực qua Health Check (`/api/health`).
3. **Loại bỏ hoàn toàn code dư thừa**:
   - Gỡ bỏ bộ Rate Limiter in-memory gây nghẽn tải.
   - Gỡ bỏ cơ chế SSL tự ký tự sinh phức tạp (không còn cảnh báo chứng chỉ không an toàn trên Safari/Chrome điện thoại).
   - Tự động mở cổng tường lửa Windows cho `5173` và `8080`.
   - Tự động copy link LAN `http://<IP_LAN>:5173` vào Windows Clipboard.

## 3. Kết Quả Kiểm Thử
- **Localhost**: `http://localhost:5173/la-so-tu-vi` -> HTTP 200 OK.
- **Proxy API**: `http://localhost:5173/api/health` -> HTTP 200 OK (chuyển tiếp tới backend 8080 thành công).
- **Mạng LAN**: Thiết bị trong cùng Wi-Fi truy cập `http://<IP_LAN>:5173` tải giao diện phát triển mới nhất, reload cập nhật tức thì.
